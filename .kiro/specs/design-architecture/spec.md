# 设计系统架构

## 目标

根据业务需求设计系统架构，包括组件、技术栈和部署方案

## 输入

- PRD（产品需求文档）
- 业务约束（预算、时间、技术栈限制）
- 非功能需求（性能、安全、可用性）

## 输出

完整的系统架构文档，包含：
- 架构概述
- 架构风格
- 系统组件
- 技术栈
- 架构图
- 数据流
- 部署架构
- 风险与应对

## 执行步骤

### 1. 需求分析
- 阅读 PRD
- 提取功能需求
- 识别非功能需求
- 明确约束条件

### 2. 架构风格选择
- 使用 #system-architect.md 角色
- 评估不同架构风格
- 选择最适合的架构风格
- 说明选择理由

### 3. 组件设计
- 定义系统边界
- 划分系统组件
- 定义组件职责
- 设计组件接口

### 4. 技术选型
- 选择编程语言和框架
- 选择数据库
- 选择缓存和消息队列
- 选择部署方式

### 5. 绘制架构图
- 使用 Mermaid 绘制系统架构图
- 绘制数据流图
- 绘制部署架构图

### 6. 风险分析
- 识别架构风险
- 提出应对措施
- 定义监控指标

### 7. 文档输出
- 编写完整的架构文档
- 包含所有必要章节
- 使用清晰的图表

## 使用方式

```
使用 spec: design-architecture

基于 PRD：
[PRD 文件路径或内容]
```
