# 代码评审

## 目标

对代码进行全面评审，确保质量、安全性和可维护性

## 输入

- 待评审的代码或改动
- 相关需求文档
- 技术设计文档

## 输出

- 评审结论（通过 / 不通过）
- 问题列表（如有）
- 改进建议

## 执行步骤

### 1. 准备评审
- 阅读相关需求和设计文档
- 了解代码改动范围
- 准备评审清单

### 2. 需求对齐检查
- 实现是否覆盖所有需求
- 是否有遗漏或超范围实现
- 验收标准是否满足

### 3. 架构一致性检查
- 是否违反架构设计原则
- 是否违反技术设计文档
- 模块边界是否清晰

### 4. 代码质量检查
- 使用 #qa-reviewer.md 角色
- 检查编码规范
- 检查代码可读性和可维护性
- 检查是否有代码重复

### 5. 测试检查
- 是否有单元测试
- 是否有集成测试
- 测试覆盖率是否合理
- 边界情况是否测试

### 6. 安全检查
- 是否有安全漏洞
- 输入验证是否完善
- 敏感信息是否保护
- 权限控制是否正确

### 7. 输出评审报告
- 汇总评审结果
- 列出问题和建议
- 给出明确的通过/不通过结论

## 使用方式

```
使用 spec: review-code

评审范围：
[指定要评审的文件或改动]
```
